# OPERATOR.md (Русская версия)

# Trader Bot Polymarket --- Руководство оператора

Это руководство объясняет:

-   какие настройки необходимо сделать перед запуском системы
-   где находятся ключи и конфигурации
-   за что отвечает каждый компонент системы
-   как просматривать рынки, предложения, алерты и результаты симуляций
-   как принимать операторские решения в режиме `semi_auto`
-   что проверить перед использованием системы в продакшене

Репозиторий проекта: https://github.com/osokolin/trader_bot_polymarket

------------------------------------------------------------------------

# 1. Что это за система

Этот проект --- **полуавтоматический операторский инструмент для работы
с Polymarket‑подобными рынками**.

Основные принципы архитектуры:

-   policy-first (политики управляют системой)
-   configuration-first
-   режим `semi_auto` по умолчанию
-   live execution отключен
-   нет полностью автономной торговли

Практически это означает, что система может:

-   получать публичные рыночные данные
-   формировать кандидаты на сделки (proposals)
-   применять политики и фильтры
-   сохранять предложения, ревью и симуляции
-   показывать состояние через CLI, Web UI и Telegram

Но **финальное решение всегда принимает человек‑оператор**.

------------------------------------------------------------------------

# 2. Общий рабочий процесс

Текущий pipeline:

1.  Получаются рыночные данные
2.  Генерируется candidate proposal
3.  Применяются policy‑проверки
4.  Proposal сохраняется в SQLite
5.  В режиме `semi_auto` proposal ожидает review
6.  Оператор проверяет и принимает решение
7.  При approve выполняется повторная валидация
8.  Все действия записываются в audit и review history

Систему нужно воспринимать как **инструмент принятия решений**, а не как
автотрейдера.

------------------------------------------------------------------------

# 3. Где находится конфигурация

Есть **два основных источника конфигурации**.

## A. Переменные окружения

Используется `.env`.

Шаблон:

`.env.example`

Основные переменные:

-   BOT_ENV
-   BOT_MODE
-   BOT_DATABASE_URL
-   BOT_UI_HOST
-   BOT_UI_PORT
-   TELEGRAM_BOT_TOKEN
-   TELEGRAM_ALLOWED_CHAT_IDS

------------------------------------------------------------------------

## B. YAML конфигурация

Runtime‑политики находятся в:

`config/`

Основные файлы:

-   base.yaml
-   balanced.yaml
-   aggressive.yaml
-   conservative.yaml
-   blacklist.yaml
-   whitelist.yaml
-   sources.yaml

В этих файлах задаются:

-   риск‑политики
-   фильтры рынков
-   правила входа

------------------------------------------------------------------------

# 4. Переменные окружения

## BOT_ENV

Окружение.

Пример:

dev prod

------------------------------------------------------------------------

## BOT_MODE

Режим работы.

Возможные значения:

paper manual_only semi_auto live_small live_full

Рекомендуемый режим сейчас:

`semi_auto`

Это гарантирует:

-   нет автоматического исполнения
-   решения принимает оператор

------------------------------------------------------------------------

## BOT_DATABASE_URL

Путь к базе данных.

Пример:

sqlite:///bot.db

Для продакшена лучше использовать:

sqlite:////var/lib/trader_bot_polymarket/bot.db

------------------------------------------------------------------------

## BOT_UI_HOST

Хост веб‑интерфейса.

Пример:

127.0.0.1

Рекомендуется запускать UI **только локально** и публиковать через
reverse proxy.

------------------------------------------------------------------------

## BOT_UI_PORT

Порт веб‑интерфейса.

Пример:

8080

------------------------------------------------------------------------

## TELEGRAM_BOT_TOKEN

Токен Telegram бота.

Получается через BotFather.

Не хранить в репозитории.

------------------------------------------------------------------------

## TELEGRAM_ALLOWED_CHAT_IDS

Список разрешённых chat id.

Пример:

123456789,987654321

Без этого бот может отвечать всем.

------------------------------------------------------------------------

# 5. Основные параметры риска

## bankroll

Определяет общий капитал для расчётов.

Контролирует:

-   размер позиций
-   дневные лимиты
-   недельные лимиты

Это **основной параметр риска**.

------------------------------------------------------------------------

## position_limits

Ограничивает:

-   размер позиции
-   число позиций
-   концентрацию по теме

------------------------------------------------------------------------

## market_filters

Фильтры рынков:

-   ликвидность
-   спред
-   категория
-   время до разрешения рынка

------------------------------------------------------------------------

## entry_rules

Правила входа:

-   минимальный edge
-   минимальная уверенность
-   требования к источникам

------------------------------------------------------------------------

# 6. База данных

bot.db

------------------------------------------------------------------------

# 9. Как принимать решения

## Важное правило

Proposal --- **это не ордер**, а предложение.

------------------------------------------------------------------------

## Перед approve нужно проверить

-   правила рынка
-   ликвидность
-   спред
-   время до разрешения
-   риск по категории
-   размер позиции
-   текущую экспозицию

------------------------------------------------------------------------

## Когда approve

Если:

-   рынок понятен
-   ликвидность достаточная
-   риск допустим
-   размер позиции разумный

------------------------------------------------------------------------

## Когда reject

Если:

-   плохая ликвидность
-   слабый сигнал
-   конфликт с текущими позициями
-   слишком близко к разрешению рынка

------------------------------------------------------------------------

# 10. Проверка продакшена

-   база данных сохраняет состояние
